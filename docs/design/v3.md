# OpenFLO v3 screens: setup, sign-in, Settings, no-login banner

Date: 2026-10-26. Design critique applied (4/5 → fixes 1–12 applied; see end). Extends the v2 prototype with critique fixes 1–12 ([`critique-v2.md`](critique-v2.md)). Covers brief screens 12, 13, 14 and the 15 "no sign-in" banner. The identity warning and the retire flow already shipped in F1.1 (`IdentityFlagCard`, `RetireSheet`); v3 does not redesign them.

**Rule:** v3 adds no new visual language. Every screen is composed from v2 atoms and molecules and the tokens in `ui/src/styles/tokens.css`. Where a new component is needed, it is named below with its atomic level.

## Contract it reads

| Screen | API |
|---|---|
| App boot | `GET /server-info` → `setup_state`, `auth.mode`, `auth.methods`, `server_address`, `version`, `instance_id` |
| Setup | `GET /setup` (steps: `auth`, `server_address`, `address_check`), `POST /setup/admin`, `PUT /settings/server-address`, `POST /settings/server-address/check`, `POST /setup/complete` |
| Sign-in | `POST /auth/login` (204, 401, 429), `GET /auth/oidc/login` (redirect) |
| Settings | `GET /me`, `GET/POST /settings/server-address/check`, `PUT /settings/server-address`, `GET/POST/DELETE /tokens`, `POST /auth/logout` |

## Boot routing (no screen; decides which screen)

1. `GET /server-info`.
2. If `setup_state = setup_required`, go to **Setup** (any URL redirects there).
3. If any request returns 401, go to **Sign-in** with `?next=<path>`. After sign-in, go back to `next`.
4. Otherwise show the app. If `auth.mode = none`, the **no-login banner** shows on every app page.

While boot loads, show the AppShell with the wordmark only. No spinner text.

## 12. First-run setup

**Template:** `WizardShell` (from F2.2: full-screen on phone, a centered 560 px column at `sm`+), with `StepDots` (3 dots) at the top. Wordmark above. One primary button per step, bottom-right at `sm`+ and full-width sticky at the bottom on phone.

Title row on every step: "Set up OpenFLO" (small, dim) above the step title (large).

### Step 1 · Your account

**basic mode**
- Title: **Your account** (every mode; the lead carries the mode)
- Lead: "You'll use this to sign in from your phone or computer."
- Fields:
  - `Field` + `Input` "Username" (autocomplete `username`, autocapitalize off);
  - `Field` + `Input` "Password" (type password, autocomplete `new-password`, show/hide `IconButton`). Hint: "At least 12 characters."
- Primary: **Continue**.
- Errors, inline under the field, never as a toast:
  - `WEAK_PASSWORD`: "Use at least 12 characters."
- If `steps.auth` is already `done` (account exists, setup resumed), the step shows "Account created · {username}" with a check, and Continue is enabled.

**oidc mode**
- Lead: "Sign-in is handled by {issuer host}." (e.g. "auth.example.com", from `oidc_issuer`)
- `ListRow` showing the issuer, with the status taken from `steps.auth`: "Connected" (ok) or "Can't reach it" (fail), with the fix "Check OPENFLO_OIDC_ISSUER and that the server can reach it."
- Primary: **Continue** (disabled until done).

**proxy mode:** same layout. The lead is "Sign-in is handled by your reverse proxy." There is no test.

**none mode:** lead "Anyone who can reach this page can use it. You can turn on sign-in later." A `Notice` (warn) links "How to turn on sign-in" to `docs/deploy.md#sign-in`. Primary: **Continue**.

### Step 2 · Server address

- Title: **Where devices find OpenFLO**
- Lead: "Your iFLO devices use this address to reach OpenFLO, from anywhere. A device keeps it until it's set up again."
- `Field` + `Input` "Server address" (inputmode `url`, placeholder `https://openflo.example.com`). It is prefilled from `server_address` when seeded.
- Hint: "Devices only connect over https://. Port 443 works best."
- Primary: **Check address**. It saves, starts the check and moves to step 3.
- Client validation (before the request): must start with `https://` and have a host. `http://…`: "Devices only connect over https://." Anything else: "Enter the full address, starting with https://".

### Step 3 · Check address

- Title: **Checking your address** while running; once results exist the verdict *becomes the title* (see Summary below)
- Lead: the address in mono. A "Change" ghost button goes back to step 2.
- A **CheckList** (new molecule, below) runs automatically on arrival. While the request is in flight, each row shows its dim label with "Checking…". This is the one place a "now" state is honest, because the server, not the device, is working.
- Results, in this fixed order, each with a plain title and status:

| check | Title | ok line | warn/fail fix line (plain) |
|---|---|---|---|
| `dns` | Found your server | "{host} points to this server." | fail: "Create a DNS record for {host} that points to this server." warn (Cloudflare): "This name goes through Cloudflare. Devices can't connect through it. Set it to DNS only (grey cloud)." |
| `tls_no_sni` | Devices can connect securely | "Works the way iFLO connects." | "iFLO connects without saying which site it wants. Your server must still answer with the OpenFLO certificate. In Caddy, set `default_sni` to this name." |
| `chain_firmware_bundle` | Certificate is one iFLO trusts | "Signed by an authority iFLO trusts." | "iFLO doesn't trust this certificate. Use a Let's Encrypt certificate." |
| `leaf_rsa` | Certificate type works | "Works with iFLO." | "iFLO needs an RSA certificate (2048-bit or larger). In Caddy, set `key_type rsa2048`." |
| `healthcheck_reachable` | This server answered | "Reached this OpenFLO." | fail: "Something else answered at this address. Check that it points to this server." When `dns` warns Cloudflare this row shows "Not checked" (dim) — the Cloudflare problem is shown once, on `dns`. |
| `port_non_443` | Port | (hidden when ok) | warn: "Port {port} hasn't been tested with iFLO yet. Port 443 is known to work." |

- Each non-ok row has a "Details" disclosure that shows the server's raw `detail` text in small mono. The raw text is never the main line.
- Summary = the step title after results (no separate summary line); the lead under it explains:
  - all ok: title "Everything checks out" · lead: the address.
  - only warns: title "Almost there" · lead "You can continue. Devices may have trouble until the warnings are fixed."
  - any fail: title "Devices can't reach OpenFLO yet" · lead "You can finish setup, but adding a device stays off until this passes."
- Secondary: **Check again** (ghost). Primary: **Continue**. It is always enabled once results exist, per FR-16: failures don't block finishing.
- Timeout or network error on the check request: one `Notice` (danger) "Couldn't run the check. Check again." The list shows dim rows.

### Step 4 · Done (not a dot; replaces the wizard body)

- A large check icon in an accent-tinted circle (the same pattern as the F2.2 done step).
- Title: **OpenFLO is ready**
- Lead: "Add your first home, then your first device."
- Primary: **Add a home**. It calls `POST /setup/complete`, then goes to Homes with the HomeSheet open.
- If the check had failures: the line under the lead reads "Adding a device unlocks once the address check passes. You can re-run it in Settings."

## 13. Sign-in

**Template:** `WizardShell` from F2.2 without `StepDots` (centered column with the wordmark; card max 400 px). No new template.

**basic**
- Title: **Sign in**
- Fields: Username (autocomplete `username`), Password (autocomplete `current-password`, show/hide).
- Primary: **Sign in**, full width.
- Errors, in a `Notice` above the fields:
  - 401: "That username and password don't match." Keep the username, clear the password, and focus the password.
  - 429: "Too many attempts. Try again in a minute." Disable the button for 60 s and show a countdown ("Try again in 42 s").
  - Network: "Can't reach OpenFLO. Check your connection."

**oidc**
- Title: **Sign in**
- Primary: **Sign in with {issuer host}**, full width. It navigates to `/api/v1/auth/oidc/login?next=…`.
- On return with an error query, show a `Notice`: "Sign-in didn't finish. Try again." For a group denial: "Your account isn't allowed to use OpenFLO. Ask the person who runs it."

**proxy:** there is no sign-in screen. A 401 shows "Your proxy didn't sign you in. Reload the page." with a **Reload** button.

The footer shows "OpenFLO {version}" in dim small text.

## 14. Settings

**Route:** `/settings`. **Entry:** a gear `IconButton` in the AppShell top bar on every app page (top right), labelled "Settings".

**Template:** AppShell, single column (max 720 px). The groups are `SectionCard`s in this order:

1. **Server address**
   - `ListRow`: the address (mono) with "Change" (opens a Sheet holding the step-2 field; saving re-runs the check).
   - A summary line with a status dot, from the last check: "Checked {relative time} · Everything checks out", "· 1 warning" or "· Devices can't connect".
   - The full CheckList: hidden behind the summary line (tap to open) when all ok, expanded otherwise.
   - Secondary: **Check again**.
2. **Units**
   - `ChoiceChips` (2): "Milliliters (mL)" and "Ounces (oz)". This reuses the `useUnits()` store from F1.2. The default follows the locale.
   - Hint: "Used everywhere in OpenFLO on this device."
3. **Sign-in** (read-only)
   - `ListRow`s: "Method": Username and password / {issuer host} / Reverse proxy / Off. "Signed in as": `me.actor`.
   - Primary for this group: **Sign out** (ghost; shown only for session actors).
   - When mode is none: the warn line "Sign-in is off" plus the docs link.
4. **API tokens**
   - Lead: "For scripts and other apps. A token can do anything you can."
   - The list uses `ListRow` per token: name; "Last used {relative or 'never'} · …{fingerprint}"; a trailing **Revoke** (`ConfirmButton`, two-step: "Revoke" → "Revoke {name}?").
   - Bootstrap tokens (`kind = bootstrap`) show the badge "From server config" and cannot be revoked here. The hint says "Remove OPENFLO_API_TOKEN to revoke".
   - Empty state: "No tokens yet."
   - **New token…** opens a Sheet:
     - name field only (tokens don't expire; "Last used" plus Revoke is the control; the API's optional `expires_in_days` is not exposed);
     - Primary **Create**.
   - Created state, in the same Sheet:
     - title "Copy your token";
     - the token in mono in a bordered box, with a **Copy** button that shows "Copied" for 2 s;
     - a `Notice` (warn): "You won't see this again. Store it somewhere safe.";
     - Primary **Done**.

     The token lives in component state only and is dropped on close (same rule as the F2.2 pairing token).
5. **About**: one `ListRow`, "Version".

## 15. No-login banner (auth mode none)

- **Organism `NoLoginBanner`:** a full-width bar above the AppShell top bar on every app page. It does not show on Setup.
- One line, warn tone, with an icon: "No login · anyone on your network can control your devices · Turn on sign-in" (link → `docs/deploy.md#sign-in`, new tab). The full explanation lives in Settings → Sign-in.
- It is not dismissible (it states a fact that stays true), but it stays one line: on phone it truncates the middle clause before wrapping, never the link.
- `role="status"`, not `alert`, so it isn't announced on every navigation.

## States checklist (each needs a test)

- **Setup:**
  - basic fresh;
  - basic resumed (account exists);
  - oidc reachable and unreachable;
  - none;
  - address validation;
  - check running;
  - all ok, warns only, any fail, check request failed;
  - done with failures.
- **Sign-in:** basic (401, 429 countdown, network); oidc (return error, group denied); proxy 401.
- **Settings:**
  - check collapsed when ok, expanded otherwise;
  - change address re-runs the check;
  - units persist;
  - token create shows the token once, never in storage;
  - revoke is two-step;
  - the bootstrap token can't be revoked;
  - sign out.
- **Banner:** shown for mode none on app pages, absent on Setup and for other modes.

## Responsive

- **360 px:** single column; sticky bottom primary in the wizard; Sheets are bottom sheets.
- **`sm`+:** Sheets become centered dialogs; the wizard is a centered column.
- **`lg`:** Settings stays a single 720 px column, because it is a list of preferences, not a dashboard.

## Copy rules applied

No "sync", "SNI", "TLS", "OIDC", "provisioning" or "token hash" in primary lines. "OIDC" appears only as the issuer's host name. "Token" is acceptable: it's the term scripts use. Technical words live only inside a Details disclosure or in a config hint (`default_sni`, `key_type rsa2048`, `OPENFLO_*`), set in mono so they read as things to type, not explanations.
